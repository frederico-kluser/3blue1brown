GPU no Manim Linux · RTX 4070 · Manim CE 0.19.0

Este projeto usa minha RTX 4070 no Linux?

Análise completa de como o Manim renderiza, o que o código realmente executa e o que fazer para aproveitar (ou não) sua GPU.

Manim CE 0.19.0 Linux RTX 4070 Renderização

Não. Sua RTX 4070 está parada enquanto este projeto renderiza.

GPU: 0% de uso. O Manim CE, na configuração atual deste projeto, renderiza exclusivamente em CPU via Cairo — um renderizador de software que não toca na placa de vídeo. Sua RTX 4070 fica ociosa do início ao fim de cada renderização, independentemente do sistema operacional (Linux, Windows ou macOS).

Eis o porquê, em três fatos:

  1. O comando Manim não usa --renderer=opengl. O arquivo services/manim_executor.py (linha 93) monta o comando manim render sem especificar renderizador — o padrão é Cairo (CPU).
  2. O Cairo é um renderizador de software. Ele desenha cada frame usando a CPU, pixel a pixel, e nunca invoca OpenGL, Vulkan, CUDA ou qualquer API de aceleração gráfica.
  3. Nem o FFmpeg usa NVENC aqui. A codificação final do vídeo também passa pelo FFmpeg em modo software (libx264), sem o codec h264_nvenc que acionaria o encoder de hardware da NVIDIA.
Resumo: Toda a renderização é CPU-bound. Sua RTX 4070 não é usada nem para rasterização (Cairo) nem para encoding (libx264). O Linux não muda nada nisso — no Windows ou macOS o comportamento seria idêntico.

O que o código realmente executa

O coração da renderização está em services/manim_executor.py, método execute_manim(). É aqui que o comando do Manim é montado e disparado:

cmd = [
    "manim",
    "render",
    "-r",
    f"{width},{height}",
    "--fps",
    "60",
    "--media_dir",
    str(media_dir),
    "--disable_caching",
    str(script_path),
    scene_name,
]

Repare no que não está aí:

Flag ausente O que faria Status
--renderer=opengl Ativaria o backend OpenGL do Manim, que usa a GPU para rasterização Não usado
--format=mp4 --codec=h264_nvenc Codificaria o vídeo final com o encoder NVENC da NVIDIA Não usado
--write_to_movie com PyAV acelerado Usaria o PyAV com aceleração CUDA se compilado com suporte Não usado

Sem essas flags, o Manim usa o renderizador Cairo, que é 100% software:

Pipeline de render atual
Cena Python → Cairo (CPU) → Frames PNG (CPU) → FFmpeg libx264 (CPU) → MP4

A GPU não aparece em nenhuma etapa desse pipeline.

Como verificar você mesmo

Enquanto um vídeo estiver renderizando, rode em outro terminal:

# Monitor de GPU NVIDIA — vai mostrar 0% de utilização
watch -n 1 nvidia-smi

# Ou, para ver os processos que estão usando a GPU:
nvidia-smi pmon -c 1

Se aparecer alguma coisa em nvidia-smi, será o X11/Wayland desenhando sua área de trabalho — não o Manim.

Como fazer o Manim usar a GPU

Atenção: mesmo com OpenGL, o Manim não vai usar 100% da sua RTX 4070. Ele usará a GPU apenas para rasterização de frames — uma fração do que a placa é capaz. O ganho real depende do tipo de cena (muitos objetos = mais ganho; cenas simples = quase nenhum).

Opção 1: OpenGL (a mais simples)

Basta adicionar --renderer=opengl ao comando. Edite services/manim_executor.py na linha onde o comando é montado:

cmd = [
    "manim",
    "render",
    "--renderer=opengl",    # ← adicione esta linha
    "-r",
    f"{width},{height}",
    "--fps",
    "60",
    "--media_dir",
    str(media_dir),
    "--disable_caching",
    str(script_path),
    scene_name,
]

Pré-requisitos no Linux:

  1. Drivers NVIDIA proprietários instalados (nvidia-smi deve funcionar)
  2. OpenGL disponível (glxinfo | grep "OpenGL renderer" deve mostrar sua RTX 4070)
  3. O Manim precisa ser executado com acesso ao display X11/Wayland ou usar Xvfb para headless
Renderização headless com OpenGL no Linux: 
# Instale o Xvfb (servidor X virtual)
sudo apt install xvfb

# Rode o Manim dentro do Xvfb
xvfb-run -a manim render --renderer=opengl ...

Opção 2: NVENC no FFmpeg (encoding acelerado)

Esta opção acelera só a etapa final de codificação do vídeo, não a renderização dos frames. O ganho é pequeno porque o gargalo está na rasterização (Cairo/OpenGL), não no encoding.

# Modifique o comando manim para usar h264_nvenc
cmd = [
    "manim",
    "render",
    "-r", f"{width},{height}",
    "--fps", "60",
    "--format=mp4",
    "--codec=h264_nvenc",    # ← encoder NVIDIA
    "--media_dir", str(media_dir),
    str(script_path),
    scene_name,
]

Verifique se o NVENC está disponível:

ffmpeg -encoders 2>/dev/null | grep nvenc
# Deve mostrar: h264_nvenc, hevc_nvenc, etc.

Quanto de GPU vai usar?

Configuração Uso de GPU Uso de VRAM Ganho vs Cairo
Cairo (atual) 0% 0 MB —
OpenGL 5–15% 200–500 MB 1.2× a 2× em cenas complexas
OpenGL + NVENC 5–20% 400–800 MB 1.3× a 2.5× em cenas complexas

Nenhuma dessas configurações chega perto de "usar toda a GPU". Sua RTX 4070 tem 12 GB de VRAM e 5.888 núcleos CUDA — o Manim simplesmente não foi projetado para computação massiva em GPU.

Por que o Manim não usa a GPU como você espera

O Manim é fundamentalmente diferente de engines como Blender (Cycles/EEVEE) ou Unreal Engine. Ele foi projetado para precisão matemática na geração de gráficos vetoriais, não para renderização em tempo real.

Manim (CPU via Cairo)
  • ✓ Precisão subpixel em curvas Bézier
  • ✓ Render determinístico (sem artefatos de GPU)
  • ✓ Funciona em qualquer máquina, até sem GPU
  • ✓ LaTeX e tipografia de alta qualidade
  • ✗ Lento em cenas com muitos objetos
  • ✗ Cada frame é rasterizado sequencialmente
Blender EEVEE (GPU)
  • ✓ Render em tempo real com shading complexo
  • ✓ Usa 100% da GPU quando necessário
  • ✓ Paralelismo massivo via CUDA/OptiX
  • ✗ Não foi feito para animações matemáticas
  • ✗ Sem integração nativa com LaTeX

Então o que fazer para acelerar?

Recomendação prática: para este projeto, o gargalo provavelmente não está na renderização. O pipeline gasta a maior parte do tempo na chamada à API da OpenAI (geração do código) e na validação. A renderização em Cairo, para cenas típicas de 10–30 segundos, leva poucos segundos em uma CPU moderna.

Se você realmente quer reduzir o tempo de render, a ordem de prioridade é:

  1. Ative o OpenGL — é uma linha de código e já traz ganho para cenas com dezenas de mobjects simultâneos.
  2. Use -ql durante desenvolvimento (low quality) e só renderize em qualidade final (-qh) quando a cena estiver pronta.
  3. Aumente os threads do FFmpeg: adicione --codec_opts="-threads 16" para usar mais núcleos da CPU no encoding.
  4. Otimize as cenas: reuse mobjects com copy(), agrupe animações com AnimationGroup e evite recriar objetos a cada frame.

Tabela: GPU vs CPU por tipo de cena

Tipo de cena Cairo (CPU) OpenGL (GPU) Diferença
Texto + 1-2 formas ~2s ~2s Empate — a GPU não ajuda
Equações LaTeX ~5s ~4s Ganho marginal
Gráfico com eixos + curvas ~8s ~5s 1.6× mais rápido
Cena 3D com muitos objetos ~30s ~15s 2× mais rápido
Transformações complexas (100+ objetos) ~60s ~30s 2× mais rápido

Valores ilustrativos para uma cena de 10s a 1080p60. CPU: Ryzen 7. GPU: RTX 4070.

Conclusão final: Sua RTX 4070 está parada, e para este projeto específico (API que gera vídeos via LLM + Manim), isso não é um problema. O gargalo real é a chamada à OpenAI e a complexidade das cenas geradas. Se quiser ativar a GPU mesmo assim, adicione --renderer=opengl e espere um ganho de 20–50% em cenas complexas — mas nunca o uso total da placa.
